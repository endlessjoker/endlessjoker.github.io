# 同一个「都是」怎样查到不同的记忆

Transformer 与开源大模型 · 第 11 讲

「法国的首都是巴黎。德国的首都是」。在 DeepSeek-V4.1-Flash 里，两个「都是」都分到 token 3139。普通词向量查的是同一行。Engram 对最新几个 token 一起取地址。两次「都是」的二元组相同，三元组不同，取出来的向量也不再一样。

第 7 讲的 MoE 要先算出隐藏表示，再决定选哪个专家。Engram 的地址只需要 token 编号，刚收到输入就能算，也能趁前面的层在工作时去取表。查表负责把一段常见的局部组合转成向量，后面的门控才看上下文决定加多少。[《Conditional Memory via Scalable Lookup: A New Axis of Sparsity for Large Language Models》](https://arxiv.org/html/2601.07372v1) · [V4.1 技术报告 §2.4.2](https://arxiv.org/html/2609.19969v1#S2.SS4.SSS2)

## 先把词表折叠，再算地址

Engram 把「the」「 The」「THE」的原始 ID 1805、455、20852 都映射成查表编号 237。分词仍按原模型进行。只有查记忆之前，才把 ID 映射到规范化后的 99,092 个内部编号。这个例子里，「首」从 2793 变成 2379，「都是」从 3139 变成 2665。[V4.1 的分词折叠和哈希实现](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/blob/314113f8a7dadb388215396ba5fbee2c610a04d6/inference/engram.py)

以「都是」结尾，从右向左取当前和前面的编号。每个编号乘本层给这个位置定好的常数，再把乘积按位异或。二元组用最右边两项，三元组多取一项，四元组再多取一项。句子开头不够时补上专用的编号。每个长度有 8 张子表。它们用不同的素数做取模，再加各自的起始偏移，同一串输入就有了 24 个确定的地址。

下表只列第 1 层每种长度的第 0 个头。层和 token 位置都从 0 开始。

| 结尾位置 | 二元组地址 | 三元组地址 | 四元组地址 |
|---|---:|---:|---:|
| 法国后的「都是」，位置 2 | 8,624,681 | 130,427,717 | 265,662,374 |
| 德国后的「都是」，位置 7 | 8,624,681 | 132,793,777 | 263,849,387 |

第一个地址可以直接复算。只看这个头，二元组共用一个取模数 16,000,057，且这张子表从 0 开始。代码随后多取一个「法国的」或「德国的」，看到地址如何分开。

```python
a = 76632096046245
b = 4839876093313
c = 35959672319349
h2 = (2665 * a) ^ (2379 * b)
print(h2 % 16000057)
for earlier in (78098, 68652):  # 法国的，德国的
    h3 = h2 ^ (earlier * c)
    print(128000880 + h3 % 16000189)
# 8624681
# 130427717
# 132793777
```

哈希可能撞地址。换八种取模，碰巧在一张表撞上，未必在另外七张也撞上。另一方面，如果二元组完全相同，八个二元组地址就全相同。切成「前七项再追加一项」实跑发布版查表器，末尾地址和一次输入八项一致。

## 同一行二元组，为什么一个结果是负的，一个是正的

每张子表取 256 维。第 1 层的 24 行接成 6144 维，再送进一张 `[25600, 6144]` 的投影矩阵。前 20480 维给四条残差流各一条键，最后 5120 维是一条共用的值。第 0 个二元组头查到的实际 FP8 行，在第一组里存的第一个数是 `−88`，缩放因子为 `1/128`，还原为 `−0.6875`。[发布版 Engram 与 FP8 行还原](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/blob/314113f8a7dadb388215396ba5fbee2c610a04d6/inference/model.py)

下面算共享值的第 0 维。用官方表行和这一维的投影权重反量化到 FP32，把点积按二、三、四元组各自的 2048 项拆开看。

| 位置 | 二元组贡献 | 三元组贡献 | 四元组贡献 | 合计 |
|---|---:|---:|---:|---:|
| 法国后的「都是」 | −0.770124 | +0.098743 | −0.060832 | −0.732213 |
| 德国后的「都是」 | −0.770124 | +0.117132 | +1.175031 | +0.522038 |

这次变号主要来自四元组。第二个「都是」的四元组还带上句号。表里是投影后的共享值，未乘真实残差流决定的门。发布实现给每条流计算与本流的键有多合拍，再用带符号的平方根和 sigmoid 得到门值。四条流加的是同一个值，份量可以不同。V4.1 也去掉了原论文的短卷积，这个投影出来的值在这一模块不再经过那一步。

两层 Engram 的表共约 1966 亿项。一个 token 在每层只取 24 行，两层原始 FP8 表值合计 `2 × 24 × 256 = 12,288` 字节，缩放和投影另算。这里的「记忆」是训练过的参数，聊天时只是按地址读。窗口里用户刚说过的话，仍要由上下文和 KV 缓存处理，和这两张固定表是两回事。
