# 为什么注意力需要 Q、K、V

AI 技术的来路 · 第 4 讲

很多介绍一上来就说：Q 是查询，K 是键，V 是值。然后摆出一条公式，让人继续猜。

先把名字放下。假设你打开通讯录，想找小陈的电话号码。

你手里有“小陈”这个查找条件；记录里有供比较的姓名；找到以后，真正要取回的是号码。**查找用的信息与取回的信息，可以不同。**

这就是理解 QKV 的入口。通讯录只是类比；神经网络里没有预先填好的姓名栏，下面会把它还原成数值计算。

## 从上一讲已经有的东西开始

上一讲，解码器拿着自己的状态，与每个输入位置的表示打分，再按权重混合这些表示。

翻译到一半，解码器的状态表达“这一步需要什么”；输入位置的表示负责被比较，同时还负责提供内容。

将这三个角色命名：

- **Q（query）**：本次读取的条件。
- **K（key）**：每个候选位置供匹配的表示。
- **V（value）**：每个候选位置实际提供的内容。

“条件”和“内容”在这里都是向量。它们不必能翻译成一句人话。

QKV 并不是 2017 年突然出现的三个神秘部件。Sukhbaatar 等人的[《End-To-End Memory Networks》](https://arxiv.org/abs/1503.08895)（2015）已经让记忆的匹配表示与输出表示有所区分。Miller 等人的[《Key-Value Memory Networks for Directly Reading Documents》](https://arxiv.org/abs/1606.03126)（2016）进一步明确采用键和值的不同编码。

这些工作提供了一条清楚的历史线索：**从“回头读”发展到“根据一种表示定位，再读取另一种表示”。**不能因此把所有注意力都说成来自单一祖先，也不能说键值存储是神经网络发明的。

## 为什么不拿输入直接比较

当然可以。令 Q、K、V 都等于输入，也能得到一种注意力计算。三者不必须使用不同的数值。

但这样等于强迫一份表示同时满足几项要求：既适合表达读取需求，又适合被匹配，还适合向后传递内容。

以“猫追老鼠”为例，“追”与“猫”不是同义词。假如某次计算需要找施事者，我们希望动作位置能接上相关实体，不必先让二者在原始空间里变得很相似。

分别做变换，就给了模型调整匹配关系的自由。原始点积 xᵢ·xⱼ 是对称的；分别用 WQ 和 WK 变换之后，“位置 i 向位置 j 取信息”的分数不必等于反方向的分数。

这里说的是分数。即使原始分数对称，逐行 softmax 之后的权重也不一定对称，因为每一行的分母可能不同。

V 再单独变换，则让送出的内容不必完全服从匹配需要。实际模型是否需要这种自由、如何共享参数，仍然可以做实验比较。

## 三份向量从哪里来

在常见 Transformer 自注意力中，同一层输入 X 分别乘三组参数：

```text
Q = X WQ
K = X WK
V = X WV
```

X 是当前各位置的表示。第一层之前，它通常来自词元嵌入与位置信息；后面各层拿到的则是前一层输出。

WQ、WK、WV 是训练学到的矩阵。它们在不同位置之间共享，同一层不需要给每个词另造一套矩阵。Q、K、V 是这次输入算出的结果，会随着输入改变。

因此 Q 不是“用户问句”的缩写。即使只输入“今天下雨了”，每个位置也可以产生自己的 Q，向允许访问的其他位置读取信息。

跨注意力的来源不同：Q 来自正在读取的一侧，K、V 来自被读取的一侧。翻译时，前者可来自目标句，后者来自原句。

## 真正算一遍

造一个极小的跨注意力例子。只有一个查询位置、三个候选位置，每个原始向量宽度为 4，暂不考虑偏置。

我们手工规定投影：WQ 和 WK 取前两个分量，WV 取后两个分量。真实模型通常会学习各分量的线性组合，这里故意只做选择，方便核算。

```text
查询位置 s = [2, 0, 9, 9]   → Q = [2, 0]

候选 x₁ = [1, 0,  2, 0]   → K₁ = [1, 0]，V₁ = [ 2, 0]
候选 x₂ = [0, 1,  0, 4]   → K₂ = [0, 1]，V₂ = [ 0, 4]
候选 x₃ = [0, 0, 10, 0]   → K₃ = [0, 0]，V₃ = [10, 0]
```

Q 分别与三个 K 做点积，得到 2、0、0。

按缩放点积注意力的规则，除以键的维度 2 的平方根，再做 softmax：

```text
缩放后的分数 ≈ [1.4142, 0, 0]
权重         ≈ [0.6728, 0.1636, 0.1636]
```

最后，权重乘的是 V：

```text
输出 ≈ 0.6728 × [2, 0]
     + 0.1636 × [0, 4]
     + 0.1636 × [10, 0]
     ≈ [2.9815, 0.6543]
```

最后一行用未四舍五入的权重计算。现在可以直接看到区别：第三个候选匹配得不突出，但它的 V 第一项很大，仍会对输出产生明显影响。**权重大小与最终贡献大小并不是一回事。**

如果保持 K 不变，只修改 V，权重不会变，取回的结果却会变。反过来，只修改 K，可以改变分配比例，而不必改变每条记录携带的内容。

这才是将两种角色拆开的实际意义。

## 公式只是把刚才几步摞起来

多个查询一起算，常见写法就是：

```text
Attention(Q, K, V) = softmax(QKᵀ / √dₖ) V
```

公式与维度可对照 [PyTorch《scaled_dot_product_attention》文档](https://docs.pytorch.org/docs/stable/generated/torch.nn.functional.scaled_dot_product_attention.html)。这里省略遮罩和 dropout。

若有 3 个查询、5 个候选，键和查询宽度都是 2，值宽度是 4：

| 运算阶段 | 尺寸 | 一行表示什么 |
|---|---|---|
| Q | 3 × 2 | 一个查询 |
| K | 5 × 2 | 一个候选的匹配信息 |
| QKᵀ | 3 × 5 | 某个查询给五个候选的分数 |
| 按行 softmax | 3 × 5 | 该查询如何分配权重 |
| 再乘 V（5 × 4） | 3 × 4 | 该查询最终取回的内容 |

除以 √dₖ，是为了缓和维度增大时点积分数容易变大的现象，避免 softmax 过早变得极端尖锐；这依赖分量尺度等统计条件，不是任何输入都能被自动规范好。

V 的宽度不必等于 Q、K 的宽度。必须对上的是：Q 和 K 能做点积；权重对应的候选数与 V 的行数一致。

[《Attention Is All You Need》](https://arxiv.org/abs/1706.03762)（2017）把这种读取方式组织成多头注意力。每个头可以有自己的投影，读出的结果再拼接、变换。头的职责由训练形成，并没有规定某个头专门管主语。
