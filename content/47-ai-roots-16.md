# Mamba：不存完整注意力矩阵，还能怎样处理序列

AI 技术的来路 · 第 16 讲

读一本书，有两种很不同的办法。你可以保留每一页，需要时重新翻找；也可以不断更新笔记，只留下认为有用的内容。

这个比喻不能代替算法，却能指出注意力与状态模型的一个关键差别。注意力允许当前位置直接访问过去各位置的表示。状态模型把过去的信息不断汇入一份状态，后面主要通过这份状态使用过去。

第 1 讲的 RNN 已经这样做过。既然如此，Mamba 为什么还值得单独讲？

## 从 RNN 到状态空间模型

先看一条最简单的更新规则：

```text
新状态 = A × 旧状态 + B × 当前输入
输出   = C × 新状态
```

状态通常是向量，A、B、C 是相应的变换。它把一个持续变化的过程写成“怎样更新内部状态”和“怎样从状态读出结果”。

这类形式有很长的控制理论背景。进入深度学习后，难点在于怎样让状态稳定保存长距离信息，以及怎样高效训练。

Gu 等人的[《Efficiently Modeling Long Sequences with Structured State Spaces》](https://arxiv.org/abs/2111.00396)提出 S4，用经过设计的状态空间结构处理长序列。这里的“结构”不是装饰：随便给一个大矩阵，既可能难训练，也可能算得很贵。

当状态更新是线性的，且相关系数不随输入位置改变时，同一过程还可以展开成卷积形式。训练就不一定非得像普通 RNN 那样，逐个位置串行执行。

但固定的更新规律也带来一个问题：读到重要内容和无关内容时，是否应该用同一种方式改写记忆？

## 关键在于：这一项值不值得留下

设任务是记住最近一次明确指定的目标数字。输入依次为：

```text
“目标是 7” → “无关编号是 100” → “目标改为 3”
```

我们希望内部记忆依次是 7、7、3。

用一个自制的标量模型表示：

```text
h新 = a × h旧 + b

目标是 7：      a=0，b=7 → h=7
无关编号 100：  a=1，b=0 → h=7
目标改为 3：    a=0，b=3 → h=3
```

这里的 a 决定保留多少旧内容，b 决定写入什么。这些数是人为设置的，用来说明选择机制，不是 Mamba 实际使用的参数。

真实模型要从输入中学会这种选择。Gu 与 Dao 的[《Mamba: Linear-Time Sequence Modeling with Selective State Spaces》](https://arxiv.org/abs/2312.00752)（2023）让部分状态空间参数依赖当前输入，从而按内容控制信息的传播和遗忘。

“选择性”就落在这里。看到什么，影响怎样更新状态。

## Δ、B、C 分别在控制什么

把刚才的人造开关换回真实计算，需要先区分连续系统与离散序列。

连续时间的线性状态空间方程写作：

```text
dh/dt = Ah + Bx
y = Ch
```

输入 x 进入状态 h，A 控制状态自身怎样变化，B 控制怎样写入，C 控制怎样读取。序列模型每次收到一个 token，因此要把连续变化转换成一次离散更新。

以对角 A、每一步内输入固定的零阶保持离散化为例：

```text
Āt = exp(Δt A)
B̄t = A⁻¹(exp(Δt A) − I) Bt
ht = Āt ht−1 + B̄t xt
yt = Ct ht
```

Δ 可以理解为本步让连续系统推进多远。Mamba 让 Δ、B、C 由输入产生；A 则是训练学习、跨时间复用的参数。不要把“输入相关”理解成所有参数都重新生成。

一个通道有 N 维状态时，对角 A 的每个元素对应一种衰减速度。B 将当前输入写入这些状态分量；C 决定本次从各分量读出什么。Δ 同时影响旧状态的保留，以及当前输入如何进入更新。

用最简单的连续系统 `A=−1、B=1` 手算，精确离散化得到：

```text
h新 = exp(−Δ)h旧 + [1−exp(−Δ)]x
```

若旧状态为 7，当前输入为 3：

| Δ | 旧状态系数 | 新输入系数 | 新状态 |
|---|---:|---:|---:|
| 0.01 | 0.99005 | 0.00995 | 约 6.9602 |
| 1 | 0.36788 | 0.63212 | 约 4.4715 |
| 5 | 0.00674 | 0.99326 | 约 3.0270 |

在这个特例里，小 Δ 倾向于保留，大 Δ 倾向于更新。真实网络还有输入相关的 B、C，不能只看 Δ 一个数就确定行为。

### 论文里的离散化与代码还有一步区别

原始 Mamba 的参考实现对状态转移使用指数，对输入项使用 `Δ×B×x` 的实现形式，并没有逐项照搬上面的精确 B̄。对应代码可查[官方 selective_scan_ref](https://github.com/state-spaces/mamba/blob/main/mamba_ssm/ops/selective_scan_interface.py)。

所以，上表用来说明连续系统与门控的关系；如果要复现官方算子，就得按实现计算。把两者混为一谈，手算常会和代码对不上。

接下来按参考实现做一次两维状态更新。省略批次，单个输入通道，状态维度 N=2：

```text
h旧 = [1, 2]
A = [−1, −2]
x = 3，Δ = 0.5
B = [1, 0.1]，C = [1, −1]

保留系数 = exp(ΔA) ≈ [0.60653, 0.36788]
写入量   = ΔBx = [1.5, 0.15]
h新      ≈ [2.10653, 0.88576]
y        = C·h新 ≈ 1.22077
```

C 没有改变保存的状态，但改变了读出结果；B 改变写入位置；A 和 Δ 共同改变过去影响衰减的速度。到这里，“选择留下信息”才落到了具体运算上。

## 它与 LSTM 的差别在计算依赖里

标准 LSTM 的门通常同时依赖当前输入 xt 和上一隐藏状态 ht−1。因此，不先算出前一步隐藏状态，后一步门也不能确定。

原始 Mamba 中，选择参数由当前层输入经过投影、短因果卷积等操作得到；它们不需要等待当前 SSM 扫描中的 ht−1 才能确定。这使整段输入的更新系数可以先算好，再处理状态递推。

两者都能控制记忆，但“系数能否提前计算”决定了后面能不能使用并行扫描。这是算法执行上的实质区别。

一个 Mamba 块也不只有这条递推。输入投影后分成两路，一路经过短卷积、激活和选择性 SSM；另一路经过激活形成乘性门；两路合并后投影回模型宽度，再与残差路径相接。短卷积负责邻近信息，SSM 负责沿长序列传递状态。

## 参数随输入变化，又怎样并行

输入相关的更新破坏了原先那种固定卷积形式。难道又得完全回到逐步等待？

看两步简单更新：

```text
第一步：h₁ = a₁h₀ + b₁
第二步：h₂ = a₂h₁ + b₂

合起来：h₂ = (a₂a₁)h₀ + (a₂b₁+b₂)
```

每一步都可以用一对数 (a,b) 表示。两步能合成一步，合成后的结果仍然是同一种形式。

而且这种合成满足结合律。于是可以先在不同小段里合并，再合并小段的结果，形成并行扫描。这里的前提是，相关更新系数可以由输入预先计算；不能把任意依赖上一隐藏状态的非线性 RNN 都这样处理。

真实 Mamba 使用更复杂的向量状态和适合 GPU 的实现。这个小例子只说明：数学上存在先后关系，并不意味着训练时必须按最朴素的方式逐项执行。

## 为什么实验要故意打乱要记住的内容的位置

只让模型记住“开头几个符号，固定延迟后输出”，可能测不出内容选择：网络学会固定位置的搬运就够了。

Mamba 论文的选择性复制任务随机改变有效 token 之间的间隔，要求过滤无关内容。图 4 的架构—序列层组合中，Mamba 架构配 S4 层准确率为 56.4%，换成选择性的 S6 层为 99.8%；无门架构从 S4 的 18.3% 到 S6 的 97.0%。[《Mamba: Linear-Time Sequence Modeling with Selective State Spaces》第 4.1.1 节](https://arxiv.org/html/2312.00752v2)

这个对照比“我们的大模型超过某模型”更能回答机制问题：外围架构相同时，换掉状态层仍有明显差异；外围结构变简后，选择性也仍有作用。

用自制输入表示，就是从固定的 `A B C 空 空 空 → A B C`，换成 `空 A 空 空 B 空 C → A B C`。要记的是内容，不再能靠一个固定延迟全部搬过去。

这种合成实验隔离了某种能力，但语言任务还需要精确检索、组合推理等更多能力。它证明选择机制解决了这个障碍，不等于证明状态模型在所有任务上替代了注意力。

## “线性”具体省在哪里

稠密全局注意力需要处理大量位置对。长度从 N 变成 2N，位置对数量会从 N² 变成 4N²。

对于模型宽度和状态尺寸固定的 Mamba，序列模块的主要工作量可以随序列长度近似线性增长。逐步生成时，每层维护状态，不必为这个状态空间模块保存随历史长度增长的完整键和值。

但这不等于训练只占固定内存。训练仍有激活、梯度、批次等开销；实际模块还包含投影、短卷积等操作。说清楚讨论的是哪一部分，才不会把一个复杂系统误读成“一份小笔记解决一切”。

## 笔记也会漏掉后来才发现有用的事

假设读完十万条随机编号，突然问：“第 61,327 条是什么？”

如果状态容量有限，之前又不知道将来会问哪一条，就很难保证把所有随机编号完整保留下来。压缩历史必然涉及取舍。

注意力保留逐位置表示，给直接访问提供了便利；但它同样不保证一定检索正确，也要承担存储和计算成本。

因此，不能只凭“线性复杂度”就宣布准确率更高。任务需要持续汇总，还是经常精确回查？状态有多大？训练是否教会了模型选择？这些都会影响结果。

Mamba 的意义，是把“怎样筛选历史”和“怎样高效更新状态”一起作为设计对象。它让我们看到：Transformer 之后，序列建模仍然有不同路线。
