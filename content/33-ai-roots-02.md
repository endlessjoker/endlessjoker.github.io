# Seq2Seq：为什么把整句话压成一份摘要会吃力

AI 技术的来路 · 第 2 讲

把“我昨天买了一本书”翻成英文，不能逐个汉字查字典，再按原样摆过去。

两个语言的词数不同，顺序也不同。模型得先弄清原句，再组织另一句话。上一讲的循环网络能依次读入内容，却还没有说明：输入结束以后，输出怎样开始？又怎样知道该停了？

## 用两个网络接力

Seq2Seq 是 sequence to sequence 的缩写，意思是从一个序列得到另一个序列。输入可以有七步，输出可以有五步，两边不必一样长。

2014 年，Cho 等人的[《Learning Phrase Representations using RNN Encoder-Decoder for Statistical Machine Translation》](https://arxiv.org/abs/1406.1078)研究了编码器与解码器：一个网络读输入，另一个根据读出的表示生成输出。该工作把短语对的评分加入统计机器翻译系统。

同年的 Sutskever、Vinyals 与 Le 在[《Sequence to Sequence Learning with Neural Networks》](https://arxiv.org/abs/1409.3215)中，用多层 LSTM 做整句翻译。不要把这些工作想成先后交接的产品版本，它们是同一时期围绕相近困难展开的研究。

先搭一个简化的翻译器。为了看清过程，假设中文按下面六个单位切分，英文按单词切分；真实系统的分词方式可能不同。

```text
编码器读取：我 → 昨天 → 买 → 了 → 一本 → 书
                                          ↓
                                  最终状态 c
                                          ↓
解码器生成：I → bought → a → book → yesterday → 结束
```

编码器就是前一讲那种会更新状态的网络。“最终状态”是它读完以后交给解码器的数值表示。

**这里的“摘要”不是一句缩短的中文，而是一组浮点数。**如果用 LSTM，实际交接可以涉及隐藏状态、记忆状态，甚至多个层；图里统一用 c 表示，不是说只传一个数字。

## 第一个英文词从哪里来

输入结束后，解码器拿到 c，再接收一个表示“开始生成”的特殊符号。

它用这些信息给词表中的候选词打分，再将分数转成概率。假设这次选中了 I，下一步就把 I 喂回去，更新解码器状态，再预测 bought。

```text
c + 开始符号 → 对第一个词的预测
c 所初始化的状态 + I → 对第二个词的预测
更新后的状态 + bought → 对第三个词的预测
……
预测到结束符号 → 停止
```

上图省略了中间计算。c 可以用于初始化状态；另一些设计会在后续步骤持续提供它。具体如何接入，是架构选择。

这也解释了为什么两边可以不一样长：解码器不是领到六个输入，就必须吐出六个输出。它逐步生成，直到结束符号或长度限制。

词也不一定每次都选概率最大的一个。有些解码方法会保留几条候选译文，比较完整序列的分数。这属于怎样选输出，不改变编码器与解码器的基本分工。

## 训练时，下一步用谁的词

假设参考译文是 I bought a book yesterday。

训练时可以在预测 bought 的位置，把正确的 I 作为输入；在预测 a 的位置，把正确的 bought 作为输入。这种做法通常叫 teacher forcing。

模型每一步都要回答一个小问题：已经给定前面这些正确词，下一个词应该是什么？答错的损失沿着解码器，再传回编码器，推动两者一起调整。

真正翻译时没有参考答案，它只能接着自己生成的词往下写。如果第一步选错，后面的输入也跟着变了。因此，训练中每一步的预测都做得不错，不保证完整生成永远顺利。

“能把句子交给另一个网络”和“能稳定写出正确译文”，中间仍有距离。

## 固定宽度究竟限制了什么

设想有人让你听完一段话，收走原文，然后回答问题：

> 老周周二借给小李 300 元，小李周四还了 100 元，剩下的钱约好下周一还。

如果只是问“他们是不是有借款往来”，一个粗略印象就够了。若要求完整翻译，姓名、日期、金额、谁借给谁，都得保存。

固定宽度状态没有规定“只能装十个词”。它可以用分布式表示编码复杂信息，不能把它当作装满就溢出的十格数组。

困难在于：句子越复杂，需要区分的细节通常越多，但交给解码器的状态宽度没有随句长增长。训练还得学会把细节可靠地写进去，再在正确时刻读出来。实践中，这种交接方式可能成为瓶颈。

加宽状态、改善训练，都能缓解问题。也不能为了引出下一种模型，就断言早期 Seq2Seq 一遇长句必然失败。Sutskever 等人的论文报告了不错的长句结果，还发现倒转源句词序有助于优化。那是具体系统的实验结论，不宜抹掉。

## 可不可以别收走原文

如果编码器每读一个位置，都留下一份状态，解码器就有机会在翻译姓名时回看姓名，在翻译金额时回看金额。

```text
只有最终交接：读完六个位置 → 留一组最终状态
保留逐处记录：读完六个位置 → 留下六组位置表示
```

代价是要保存更多数据，而且还得解决一个新问题：**这一步应该从哪几处取信息？**

这正是下一讲要讲的注意力。它没有让模型凭空获得更大的“理解力”，而是改变了读取输入信息的方式。
