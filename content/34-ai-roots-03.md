# 注意力：翻译到一半，能不能回头看原文

AI 技术的来路 · 第 3 讲

上一讲的翻译器读完原句，把最终状态交给另一个网络。接下来即使需要一个细节，也只能从已经传过去的状态里找。

换一种做法：把原句各处的表示都留下。翻译到哪里，就重新决定这一步要读哪些地方。

这就是早期神经机器翻译注意力最容易理解的用途。

## 留下的不是一排孤立单词

Bahdanau、Cho 与 Bengio 的[《Neural Machine Translation by Jointly Learning to Align and Translate》](https://arxiv.org/abs/1409.0473)在 2014 年发布预印本，发表于 ICLR 2015。它用双向循环网络读原句，为每个位置留下表示，再让解码器在生成过程中动态读取。

双向的意思是：一个网络从左往右读，另一个从右往左读，同一位置的两份结果合在一起。

比如英文 bank 既可以指银行，也可以指河岸。读到它时，附近是 money 还是 river，可能影响应当采用哪种解释。只留这个词的字典编号，并不能表达这种区别。

位置表示包含周围信息。因此，“关注第三个位置”不等于只拿回第三个词的原始字面意义。

## 写到这一步，需要哪些信息

假设原文被切成三个位置，编码器留下 h₁、h₂、h₃。解码器准备生成下一个词时，也有自己的状态 s，记录已经生成的内容。

现在用一个可训练的打分函数，将 s 分别与三份表示配对：

```text
s 与 h₁ → 分数 e₁
s 与 h₂ → 分数 e₂
s 与 h₃ → 分数 e₃
```

“配对”究竟算什么？早期常见办法是先对两边做线性变换，将结果相加，再过一个小网络得到标量分数。这就是加性注意力的基本思路。

它不需要人工写出“生成地名时搜索地名”的规则。打分网络与翻译网络一起训练，最终译文的损失会影响这些分数怎样计算。

Luong 等人的[《Effective Approaches to Attention-based Neural Machine Translation》](https://arxiv.org/abs/1508.04025)（2015）还系统研究了其他打分方法，包括点积，以及读取全句或局部区域的不同方式。注意力从一开始就不是某个固定公式的别名。

## 分数怎样变成一份可用信息

下面是自制算例，不代表真实模型对任何句子的注意力。

设打分结果为：

```text
e₁ = ln 6，e₂ = ln 3，e₃ = ln 1 = 0
```

ln 是自然对数。选这三个数只是为了算起来方便。softmax 对分数取指数，再除以总和：

```text
指数：6、3、1
总和：10
权重：0.6、0.3、0.1
```

这些权重加起来等于 1。分数不是概率，经过这一步归一化才成为分配比例。

为了能手算，再假设三份表示只有两个分量：

| 位置 | 编码后的表示 | 这一步的权重 |
|---|---|---:|
| 1 | [1, 0] | 0.6 |
| 2 | [0, 1] | 0.3 |
| 3 | [1, 1] | 0.1 |

逐项乘权重，再相加：

```text
c = 0.6 × [1, 0] + 0.3 × [0, 1] + 0.1 × [1, 1]
  = [0.7, 0.4]
```

得到的 c 叫上下文向量。它是这一步从原句取回的信息，随后参与解码器的状态更新和词预测。

**c 还不是一个单词，也不是某个位置的编号。**注意力只是给后面的网络送去了一份加权汇总。

## 为什么不直接挑分数最高的那个

刚才位置 1 权重最大，但位置 2 和位置 3 的信息没有完全丢掉。

一个译词可能需要同时参考主语、动词和附近的限定语。允许多处信息混合，往往比强迫它只选一个位置更灵活。

还有训练上的原因：softmax 和加权求和对分数、内容都可微。输出错了，梯度可以告诉模型，哪些分数和表示该调整。直接用 argmax 选一个位置，会让“选谁”这一步难以照常用梯度学习；当然，也有其他训练离散选择的方法。

因此这里的“看”是一种连续的数值计算，没有真的移动眼睛，更不意味着模型产生了人的意识。

## 下一步会重新分配

解码器写完一个词，状态 s 变了，再算一次分数，就可能得到另一组权重。

注意力图的一行通常对应一个输出位置，一列对应一个输入位置。亮点移动，是模型每次取信息的比例在变化。

但图上某个词很亮，不能直接推出“模型只靠它作出决定”。位置表示本来就混有上下文，后面还有其他计算路径。注意力图可以帮助观察，不能独自充当完整解释。

比起固定交接，变化在这里：**每一步的 c 可以不同，原句也始终有机会被重新读取。**

这不等于问题全解决了。单次读取仍然把多个位置混成一个向量，模型仍可能漏译、重复或错误对齐。保存所有位置，也增加了存储和计算。

## QKV 已经露出轮廓

回头看刚才的过程，其实有三种角色：

| 角色 | 刚才由谁承担 |
|---|---|
| 表达这一步要找什么 | 解码器状态 s |
| 供它比较、判断相关性 | 输入位置表示 h |
| 最后实际混合、取回的内容 | 仍是输入位置表示 h |

后两项暂时由同一份表示兼任。

如果把“拿来匹配的信息”和“取回的信息”分开，会怎样？比如查通讯录时，用姓名找到一条记录，想取回的却是电话号码。
