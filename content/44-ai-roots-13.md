# DPO：只有偏好比较，怎样用来训练

AI 技术的来路 · 第 13 讲

上一讲的路线比较绕：先收集回答比较，训练一个奖励模型，再让语言模型不断生成回答、接受打分、调整行为。

如果数据已经告诉我们“这份比那份好”，能不能直接拿来更新语言模型？

Rafailov 等人的[《Direct Preference Optimization: Your Language Model is Secretly a Reward Model》](https://arxiv.org/abs/2305.18290)（2023，简称 DPO）给出了一种做法。它从带 KL 约束的奖励优化问题出发，推导出可以直接作用于偏好数据的训练损失。

这里的“直接”，省掉的是单独拟合奖励模型再做在线策略优化的那套循环；偏好数据、参考模型和训练计算仍然需要。

## 一条训练数据里有三样东西

```text
提示 x：用两句话解释为什么不能只凭考试分数判断学习效果。
较好回答 y⁺：符合要求，说明题目覆盖范围和实际应用能力的差别。
较差回答 y⁻：只说分数高，就代表所有知识都已经掌握。
```

这只是说明数据结构的自制例子。

两份回答都送进当前语言模型，分别计算它们在该提示下的概率。这里通常采用 teacher forcing：把已有回答的正确前文送进去，计算后续词元的条件概率，无须临时生成一份新回答。

一整份回答的概率来自逐词元概率的乘积。实现时使用对数，把乘积变成加法，避免数值太小。

所以，计算“模型有多大概率写出这份回答”，与真的运行采样把它写一遍，是两回事。

## 为什么还要有一份参考模型

DPO 通常保留一份冻结的参考模型，例如监督微调得到的初始模型。它也给这两份回答计算概率。

比较不只看当前模型是否更喜欢 y⁺，还要看：**相对于参考模型，这种偏好增强了多少。**

记当前模型为 π，参考模型为 πref，先写两项：

```text
a = log π(y⁺|x) − log πref(y⁺|x)
b = log π(y⁻|x) − log πref(y⁻|x)
```

a 衡量较好回答相对参考的变化，b 衡量较差回答相对参考的变化。DPO 用它们的差构造训练目标：

```text
z = β × (a − b)
损失 = −log sigmoid(z)
```

β 是一个控制目标尺度、与原来 KL 正则化强度相关的超参数。它不是“更好回答应该长多少”的系数，也不能脱离数据与训练设置，简单解释成越大越好。

## 把概率代进去算一次

为方便手算，假设两份短回答的序列概率如下。剩余概率分配给其他回答，所以两列不需要加起来等于 1。

| 模型 | 较好回答 y⁺ | 较差回答 y⁻ | 两者概率之比 |
|---|---:|---:|---:|
| 冻结参考模型 | 0.20 | 0.10 | 2 |
| 当前模型 | 0.30 | 0.05 | 6 |

当前模型对较好回答的相对优势，从 2 倍变成 6 倍。再与参考相比，是 3 倍：

```text
a − b = log(0.30 / 0.20) − log(0.05 / 0.10)
      = log 3
```

仅为演示，取 β = 1：

```text
sigmoid(log 3) = 3 / 4 = 0.75
损失 = −log 0.75 ≈ 0.2877
```

如果当前模型与参考完全相同，a 和 b 都为 0，损失约为 0.6931。这个例子里，向正确偏好方向变化后，损失降低了。

0.75 是此偏好模型对这一对回答构造出的比例，不是“较好回答有 75% 的事实正确率”，也不是当前模型生成它的概率。当前模型的生成概率在表中是 0.30。

## 奖励为什么能换成概率比

上一节会算损失了，但为什么偏偏是这个式子？要从上一讲 RLHF 的目标接过来。

取 β>0，并假定参考模型对所比较回答赋予非零概率。先固定一个提示 x。把可能回答记为 y，把模型分配给它的概率记为 p(y)，参考概率记为 q(y)。我们希望最大化：

```text
J = Σy p(y) r(y) − β Σy p(y) log[p(y)/q(y)]
```

第一项是平均奖励。第二项惩罚偏离参考模型，β 决定惩罚强度。若只顾第一项，模型可以把概率集中在某个高分回答上，哪怕奖励器被它骗了。

所有回答的概率还必须加起来等于 1。引入一个系数 λ，将这个约束加进目标：

```text
J约束 = J + λ(Σy p(y) − 1)
```

暂时把每个回答的概率当作可自由调整的变量，对 p(y) 求导并令其为零：

```text
r(y) − β{log[p(y)/q(y)] + 1} + λ = 0

整理后：p*(y) ∝ q(y) exp[r(y)/β]
```

星号表示理想最优策略。比例关系还缺一个归一化分母 Z，使所有概率之和为 1：

```text
p*(y) = q(y) exp[r(y)/β] / Z

反过来解奖励：
r(y) = β log[p*(y)/q(y)] + β log Z
```

这一步揭示了关键联系：在这套目标下，一个回答相对参考模型被提高了多少，可以对应它的奖励。Z 很难计算，因为要遍历可能回答；但同一道题的两份回答共用 Z，做差时就抵消了。

再引入 Bradley–Terry 偏好模型。它用 sigmoid(奖励差) 表达“人选择较好回答”的概率：

```text
P(y⁺ 胜过 y⁻) = sigmoid[r(y⁺) − r(y⁻)]
```

把刚推导的奖励表达式代入，Z 消失，就得到前面的 DPO 损失。实际训练用可训练的 πθ 来参数化这个概率比，不需要先把最优策略求出来。

推导可对照[《Direct Preference Optimization》附录 A.1—A.2](https://arxiv.org/html/2305.18290v2)。这里展开的代数说明了为什么能省掉独立奖励网络；有限模型、有限偏好样本上的优化，并不等于无条件求出了真实人类偏好的最优解。

## 一次更新具体推动什么

令 m = a − b，即相对参考的偏好优势，则损失对 m 的导数为：

```text
d损失/dm = −β × sigmoid(−βm)
```

取 β=1。如果模型与参考相同，m=0，导数为 −0.5；如果 m=log 3，导数为 −0.25。都在推动优势增大，但已经分对的例子，推动力度变小了。

再接回网络参数：m 中好回答的 log 概率带正号，差回答带负号。反向传播于是沿两条计算路径调整同一套语言模型参数。参考模型冻结，只提供比较基准。

一条回答也不是一个独立按钮。假设回答只有三个 token，条件概率为 0.5、0.2、0.1：

```text
序列概率 = 0.5 × 0.2 × 0.1 = 0.01
序列 log 概率 = log 0.5 + log 0.2 + log 0.1 ≈ −4.6052
```

训练沿这些 token 的 log 概率求和回传梯度。实现时要对齐“当前位置预测下一个 token”，并排除提示和补齐位置的损失；否则计算的就不是给定提示下回答的概率。

## 为什么不是把好回答拿来做 SFT 就行

只对较好回答做监督微调，会提高它的生成倾向，但没有直接利用“同一个提示下，另一份回答为什么不如它”这组对照。

DPO 的损失同时使用两份回答，以及它们相对参考模型的变化，提供的是比较信号。

还要小心一句常见简化：“DPO 一定把好回答的绝对概率拉高，把坏回答拉低。”目标真正关注的是相对优势。

例如参考概率仍是 0.20 与 0.10，当前变为 0.10 与 0.01。较好回答的绝对概率下降了，但两者之比从 2 变成 10，偏好损失依然可能改善。模型还会在其他回答之间重新分配概率。

这个例子说明看训练损失时，需要理解它衡量什么，不能用一句直觉替代实际目标。

## 简化了流程，数据问题还在

如果“较好回答”只是更长、更有礼貌，事实却错了，DPO 也可能学到这种倾向。比较标签不能自动提供标签里没有的信息。

如果两份回答都很差，挑出相对较好的一份，也不等于获得了理想示范。回答长度差异、重复样本、偏好矛盾等因素，都会影响训练。

标准离线 DPO 在微调步骤中不用不断从当前模型采样新回答，但此前的比较数据总要来自某处。也有持续刷新数据或使用在线反馈的变体，不能把一种标准流程说成所有偏好训练的定义。

论文中的实验表明这种方法可以有效且更简洁，但不足以说明它在任何数据与任务上都一定优于 PPO。

## 论文怎样证明它不只是让训练流程变短

原论文的 IMDb 实验先固定一个情感分类器作为已知奖励：从 25,000 个影评开头各采样四份续写，两两比较得到每题六对偏好。它比较 DPO、PPO、只学胜出回答等方法，并同时测奖励与相对参考模型的 KL；图 2 中，DPO 在这组设置下形成更好的奖励—KL 前沿。[《Direct Preference Optimization》第 6.1 节与附录 C.1](https://arxiv.org/html/2305.18290v2)

为什么要做这个受控实验？如果只比较人类更喜欢哪一份，奖励本身就带着标注误差。先固定一个可计算的裁判，可以更集中地问：两种优化方式，谁能在相近偏离程度下把目标做得更好？

也不能只比奖励最高点。假设方法 A 奖励 0.9、KL 为 30，方法 B 奖励 0.85、KL 为 3，前者可能只是更激进地放弃了原分布。要画整条曲线，才能看清交换关系。

这项实验支持优化方法有效，但“影评更积极”与“回答事实更准确”不是同一个目标。把方法用于知识助手，还得重新检查偏好标签是否真的奖励了准确性。
